# Critique of the live 8-color build (chat, 2026-10-15 ~13:40)

Reviewed: STATUS.md (13:20 handoff), DECISIONS.md, `potry.py` length gate and `rip_state`, `handcheck.py`, test suite (185 tests; the 2 OCR geometry tests error on Linux only because the test font isn't installed, fine on the PC).

**Overall:** sound. Every failure path I traced ends in cancel-and-hold, never in a bad rip. The two incidents were contained and written up straight. The over-spec additions (control window, corner warning, dashboard views) earn their keep on a shared floor PC. What follows is ordered by risk, then the answers to STATUS §6, then the spec changes made official.

## A. New risks Code didn't list (do these first)

### A1. Someone touches the mouse mid-rip
The corner warning waits for 5 s of stillness before starting, but nothing watches for input *during* the 30–90 s the driver is clicking through New → Add → RIP → Print. Add, RIP and Print are real `click_input` clicks at screen coordinates. If someone grabs the mouse, switches PO-TRY's view, or opens another window in that span, a click can land somewhere unintended. The RIP queue view has a real **Print** button.

**Fix:** during the driving sequence, poll `GetLastInputInfo` (or a low-level hook) between steps and immediately before every `click_input`. On any human input: stop, Cancel the preview if it's open, leave the run's sheets `queued` (not held: nothing is wrong with them), and show "Rip interrupted: someone used the mouse; retrying in 5 min" in the corner window. Also verify, before each real click, that PO-TRY is the foreground window and the target control is visible and enabled. Needs a test with a fake input clock.

### A2. Resuming after a long pause can re-rip hand work
Hand-check overlap is mostly a non-issue while the agent runs: it fetches every 2 min, so it nearly always gets an order before a person does, and the app flips to 1/1. The real exposure is **pause → hand work → resume**. While paused, people download, rip and print orders. Then they may delete those jobs from PO-TRY's queue (the Delete button) and tidy Downloads. On resume, the agent finds no trace and rips them again.

**Fix:**
- Record pause start/end in the ledger.
- On Resume after a pause longer than 15 min, the control window lists the orders that arrived during the pause and asks: **"Agent takes these"** or **"Mark these done by hand"**, defaulting to the second. The same applies after the agent was down: a gap between heartbeats of over 15 min, e.g. PC off overnight.
- Until someone answers, those orders aren't ripped; nothing after the pause is blocked.

### A3. Routing by "title contains" is the wrong key
The UV→CMYK overlap (STATUS §4 #12) is a symptom. "Starts with" also breaks the day someone edits a product title in Shopify. Route by **Shopify product ID** instead. Line items carry `product { id }` (GraphQL) and product IDs never change. `machines.json` lists product IDs per line; titles stay only as human labels. On startup, fetch each configured product's current title and log it, so a renamed product is visible but harmless. A line item from an unknown product that has `_Print Ready File` → dashboard flag "unrouted product", never ripped. This fixes #12 properly and is a prerequisite for CMYK/UV.

### A4. PO-TRY job tabs (raise priority of STATUS #7)
A dozen open job tabs after half a day becomes 30–40 on a busy day, each holding full-resolution images. That's the most likely cause of a PO-TRY slowdown or crash this week, and a crash mid-sequence is exactly the brittle case. Close the run's job tab after "RIP finished" is confirmed, or at least close tabs older than the last 3 before each New. If closing a tab pops a "save changes?" dialog, answer No via a named button only.

## B. Answers to STATUS §6

**1. Length gate tolerance / picture count.** The current gate is right for runs of a few big sheets and close to blind for runs of many small ones. Allowing 0–1 in per gap means a 60-picture run has ~59 in of slack, so several missing 8 in sheets pass. Don't cap picture count. Make the check do the work it claims:
- **First, try to remove the variance.** Intelligent layout's ⋮ dropdown (the unnamed half next to F3) almost certainly has a spacing setting. Probe it read-only with Kevin. If spacing can be pinned (e.g. 0.5 in), the per-gap allowance collapses to ~0.05 in and the gate becomes precise for any picture count.
- **If it can't be pinned:** when `(pictures−1) × gap_in + tolerance ≥ smallest picture length in the run`, the gate can't detect a missing picture, so verify each load instead. Add pictures one at a time and confirm after each that the selected picture's W/H matches that file's measured size (the spinners already read this). It's slower (~5 s per picture) but unattended, and only for many-picture runs. Log which mode each run used.

**2. Refuse on PO-TRY version change?** Yes, but don't brick. At startup and once an hour, read the version from the window title (`PO-TRY V2.24.1`) and the exe's file version and size. On mismatch: pause, flag "PO-TRY changed to vX: run a dry run, then confirm", and add a **"Trust this version"** button to the control window that only appears after a successful dry run on that version. Store trusted versions in `machine.json`.

**3. Unreadable queue holds everything: too blunt?** Yes for an unattended loop. Hold is a sheet-level verdict ("something's wrong with this sheet"); an unreadable table is a machine-level condition. Change it: if the queue can't be read, **skip this cycle** and touch nothing. After 3 consecutive failures, set machine state `error` with "can't read PO-TRY's queue" on the dashboard. Sheets stay `queued` and continue on their own when the read works again. The spec rule stays in spirit: never rip when you can't check.

**4. Hand-check gaps.**
- A2 above is the important one.
- Code's gap #4 (a person loads several of the agent's own queue files into one job by hand): close it by making the agent's files not look loadable. Keep unripped downloads in `8color-queue\_agent-do-not-load\`, and only move them to `ripped\{run}\` after. Then a person looking in that folder sees a name that tells them not to.
- Browser duplicate suffixes: Downloads already contains names like `…-New Gang Sheet-(1) (1).png`. Add a test that `name_position` still reads the position from those.
- "Same order#, different position → manual check" is the right call: a person probably took the whole order. Keep it.

**5. Ledger: backups or SQLite?** Keep JSON; the write is already atomic. Add a copy to `state\backups\processed-YYYYMMDD.json` on agent start and once a day, keeping 30. The ledger also grows forever: prune `ripped`/`by_hand`/`held` entries older than 60 days into a monthly archive file. SQLite only if the file passes ~5 MB.

**6. Token: rotate now, or step 7 first?** Step 7 first, then rotate. It's a read-only order token printed into a private session transcript, not published. That's real exposure (orders carry customer names and addresses) but not an emergency that justifies breaking six systems mid-shift. Do step 7 this week, which needs ~15 min of Kevin in Shopify's Dev Dashboard. Then rotate the shared token at a quiet time, with the hub thread updating the hub, scanners, paperwork printer and tracker in one go. If step 7 slips past a week, rotate anyway.

**7. Priorities.** Revised order:
1. A1 input-abort, A4 tab closing, B3 queue-unreadable → skip cycle. (Safety and stability of what's live; small.)
2. A2 pause/resume prompt.
3. B1 gate: spacing probe with Kevin, then per-picture verify if needed.
4. B2 version check.
5. Step 7 (Shopify app) → rotate shared token.
6. Code's (a) by-hand copies out of the queue folder, (b) missing file holds only that sheet, B4 `_agent-do-not-load`, B5 backups and prune.
7. A3 routing by product ID → then CMYK/UV.

**8. Over-built?** No. The corner warning is the mechanism that makes "don't touch the mouse" workable on a shared PC, and A1 completes it. Control window, search and TV views are cheap and Kevin asked for them. The real gap is the opposite: **no alerting.** A run that holds at 4 pm on a busy day sits unseen until someone looks at :8085. Add one push channel for `error` and new holds (whatever the hub already uses: ntfy, a sound on the TV view, email). No order details in the alert beyond order numbers.

## C. Spec changes made official (SPEC amended alongside this file)

- §2: routing moves to **product IDs** in committed `config/machines.json` (lines → machines). Titles are labels. Unrouted products are flagged, never ripped.
- §3: layout gains `ledger.py`, `handcheck.py`, `ocr.py`, `status.py`, `warning.py`, `control.py`, `lock.py`, `find.py`. `secrets.json` holds the Shopify credential **and** `dashboard_key`; both are secret, never logged or printed. Secret checks use `git grep` only, never a plain grep over the working folder.
- §6 rule 1, Q1 as built: a sheet's copies stay together when all of them fit under the cap, starting a new run if needed. Copies split across runs only when together they exceed the cap.
- §7: the length gate reads the Print preview by OCR (UIA can't see it). Bounds: up to the planned length + tolerance, down to planned-without-gaps − tolerance. The queue `Size` check after the rip is the backstop. Plus A1 input-abort, B1 per-picture verify when the gate can't see a missing picture, B2 version check.
- §8: the heartbeat may carry queue detail and history, under the scrub + leak test. The dashboard has detail, TV and search views and a local history DB on the Pi. Add alerting (B8).
- §9: the 60 s corner warning + 5 s stillness replaces the "idle" rule. Pause keeps the process alive. Task Scheduler has a 5-min watchdog trigger. The control window is the primary on/off. Add the A2 resume prompt.
- §4: queue unreadable → skip cycle, error after 3 (B3). Agent files live in `_agent-do-not-load\` until ripped (B4).
- Floor: `start_from_order` = 47943 recorded.
